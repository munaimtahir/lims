## Executive Summary

Core LIMS v1.0 is a production-ready Laboratory Information Management System that implements core laboratory workflows from patient registration through result reporting and billing. - ✅ Production deployment successful
- ✅ Comprehensive documentation completed

## Known Issues & Limitations

### Non-Critical Issues (Do NOT Block Production)

#### 1. PDF Download Endpoints Return 404

**Affected:**
- `GET /api/v1/reports/{report_id}/download/`
- `GET /api/v1/payments/{payment_id}/download_receipt/`

**Impact:** LOW
- Report generation works (database record created)
- Payment recording works (database record created)
- PDFs can be regenerated on-demand or accessed via alternative methods

**Workaround:** Reports and payments are in database; download helper endpoints need implementation

**Planned Fix:** v1.1

#### 2. Backend Health Check Shows "Unhealthy" (Cosmetic)

**Issue:** Backend container may show "unhealthy" in `docker ps` due to health check timing

**Impact:** NONE - System is fully operational if API responds

**Verification:**
```bash
curl http://localhost:8013/api/v1/health/
# If returns {"status":"healthy",...}, system is operational
```

**Planned Fix:** Adjust health check interval/timeout in v1.1

### Functional Limitations (By Design)

1. **Single Tenant:** One lab per deployment (no multi-tenancy)
2. **English Only:** No internationalization/localization support
3. **Desktop Optimized:** Mobile UI may need adjustment
4. **Manual Backups:** Automated backup system not included
5. **Basic Monitoring:** Health check endpoint only (no full monitoring stack)
6. **Synchronous Operations:** Most operations are synchronous (Celery configured but underutilized)

## Deployment

### Quick Start

```bash
# 1. Clone and navigate
git clone https://github.com/munaimtahir/lims.git
cd lims

# 2. Configure environment
cp .env.example .env
# Edit .env with production values (SECRET_KEY, DB_PASSWORD, ALLOWED_HOSTS, etc.)

# 3. Build and start
docker compose build
docker compose up -d

# 4. Initialize
docker compose exec backend python manage.py migrate
docker compose exec backend python manage.py seed_test_catalog --clear
docker compose exec backend python manage.py create_demo_users  # Optional

# 5. Verify
curl http://localhost:8013/api/v1/health/
```

### Requirements

**Hardware:**
- Minimum: 2 CPU cores, 4GB RAM, 20GB disk
- Recommended: 4 CPU cores, 8GB RAM, 50GB disk

**Software:**
- Docker 24+
- Docker Compose 2.20+
- Linux OS (Ubuntu 20.04+, Debian 11+, or CentOS 8+)

**Network:**
- Port 8013 available (or configure custom port)
- (Optional) Port 443 for HTTPS if using host-level Caddy

### Critical Environment Variables

```env
# Generate securely (see docs/ops/ENVIRONMENT_VARIABLES.md)
SECRET_KEY=<50+ character random string>
DB_PASSWORD=<32+ character random string>

# Must include all domains/IPs
ALLOWED_HOSTS=localhost,127.0.0.1,yourdomain.com,server-ip

# Must match frontend URLs
CORS_ALLOWED_ORIGINS=http://localhost:8013,https://yourdomain.com
CSRF_TRUSTED_ORIGINS=http://localhost:8013,https://yourdomain.com

# Database
DB_NAME=lims_db
DB_USER=postgres
DB_HOST=db
DB_PORT=5432

# Settings
DEBUG=False
DJANGO_SETTINGS_MODULE=config.settings.production
```

## Architecture

### System Architecture

```
┌─────────────────────────────────────────────────┐
│          Client (Browser)                        │
└────────────────┬─────────────────────────────────┘
                 │ HTTP(S)
┌────────────────▼─────────────────────────────────┐
│         Caddy Reverse Proxy                       │
│  (SSL termination, request routing)               │
└─┬─────────────────────────────────────────────┬──┘
  │                                             │
  │ /api/*, /admin/*, /static/*, /media/*       │ /*
  │                                             │
┌─▼─────────────────────┐    ┌─────────────────▼───┐
│  Django Backend        │    │   React Frontend    │
│  - REST API            │    │   - SPA             │
│  - Admin Interface     │    │   - Nginx serve     │
│  - Gunicorn WSGI       │    └─────────────────────┘
└─┬──────────┬───────────┘
  │          │
  │          │ Celery
┌─▼──────┐ ┌─▼─────────┐
│PostgreSQL│ │Redis      │
│Database  │ │Cache/Queue│
└──────────┘ └───────────┘
```

### Docker Services

| Service | Container | Purpose | Exposed Port |
|---------|-----------|---------|--------------|
| db | lims_db | PostgreSQL 16 database | Internal only |
| redis | lims_redis | Redis cache/broker | Internal only |
| backend | lims_backend | Django REST API | Internal only |
| celery | lims_celery | Background tasks | N/A |
| frontend | lims_frontend | React SPA | Internal only |
| proxy | lims_proxy | Caddy reverse proxy | 127.0.0.1:8013 |

**Security Note:** Only the proxy is exposed. Backend binds to 0.0.0.0:8000 inside container but is NOT mapped to host.

## Upgrade Path

### From Pre-v1.0 Builds

If upgrading from development/test builds:

1. **Backup database:**
   ```bash
   docker compose exec db pg_dump -U postgres lims_db > backup_pre_v1.sql
   ```

2. **Pull latest code:**
   ```bash
   git checkout v1.0-core-lims-ready  # Or main if v1.0 is merged
   git pull
   ```

3. **Rebuild and restart:**
   ```bash
   docker compose build
   docker compose down
   docker compose up -d
   ```

4. **Run migrations:**
   ```bash
   docker compose exec backend python manage.py migrate
   ```

5. **Verify:**
   ```bash
   python smoke_test.py
   ```

### To Future Versions

Future versions will maintain:
- ✅ Database schema compatibility (forward migrations)
- ✅ API version compatibility
- ✅ Configuration file compatibility

Upgrade procedures will be documented in future release notes.

## Support & Troubleshooting

### Getting Help

1. **Documentation:** Check [docs/](../) directory for comprehensive guides
2. **Health Check:** `curl http://localhost:8013/api/v1/health/`
3. **Logs:** `docker compose logs <service>` (backend, celery, frontend, etc.)
4. **Smoke Test:** Run `python smoke_test.py` to validate system
5. **Issues:** Open GitHub issue with logs and error details

### Common Issues

**Services not starting:**
```bash
docker compose ps  # Check status
docker compose logs backend  # Check logs
```

**Authentication failures:**
```bash
docker compose exec backend python manage.py create_demo_users
```

**Database connection errors:**
```bash
docker compose exec db pg_isready -U postgres
docker compose restart db
```

**API 404 errors:**
- Verify ALLOWED_HOSTS in .env includes your domain/IP
- Verify CORS_ALLOWED_ORIGINS includes frontend URL
- Check backend logs: `docker compose logs backend`

See [docs/ops/DEPLOYMENT.md](../ops/DEPLOYMENT.md) for complete troubleshooting guide.
